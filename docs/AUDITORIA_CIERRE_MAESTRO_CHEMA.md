## 3. Integridad y recuperación de datos

- **Un motor:** `src/domain/engine.ts::applyOperation` se reutiliza en cliente y core generado del servidor. Crear pendiente no descuenta stock. Entregar mueve galpón→alquilado. RETIRE procesa el saldo completo con distribución de incidencias; REENTER no suma otra vez. No se inventaron retiros parciales ni equivalencias físicas de cuerpos.
- **Concurrencia:** servidor verifica membresía vigente, versiones, revisión y tarea comercial estable bajo transacción/CAS. Dos UUID diferentes no autorizan dos veces la misma devolución. Última unidad concurrente, misma devolución, downgrade de rol durante commit, bootstrap de copia común y timeout después del commit se prueban en PostgreSQL17+SQLite. Los tests Auth usan además identidades reales desechables, diferenciadas de `auth.users` fixture del runner local.
- **Idempotencia y cola:** cambio local+outbox se confirman juntos. Respuesta incierta consulta recibo. El mismo ID con otro contenido se rechaza. SENDING/uncertain no se archiva como «no enviado». Deshacer conserva autor, cinco minutos, revisión y evidencia histórica; al reabrir una tarea se crea una instancia sucesora.
- **Persistencia:** fallos de lectura/escritura, esquema incompatible y datos corruptos conservan originales. No se restablece inventario silenciosamente. Las pruebas SQLite/almacenamiento simulado no acreditan falta de espacio real en Android.
- **JSON:** elegir/validar/revisar no modifica; restaurar individual requiere confirmación y conserva copia previa. En equipo abre recuperación individual aislada, nunca reemplaza el servidor ni mezcla existencias. El archivo exacto `repartos-chema-5-pedidos-whatsapp.json` no está disponible; `tests/fixtures/whatsapp-five.json` es sintético y no lo reemplaza.
- **Fotos:** referencia lógica, JPEG reducido≤1024px/calidad0.7, hash/cola por usuario+espacio y acceso privado. Fallo de subida no bloquea alquiler. El backup con fotos exige sus bytes; retención protege deshacer/copias. Cámara/galería/URI nativas siguen pendientes de aceptación.

El delta limita cinco páginas por ciclo y conserva `receivingPending`; cada página guarda cursor/watermark/confirmado/outbox antes de continuar. Deltas históricos y recibos no retienen inversos completos: sólo el último `currentLog` apropiado permite deshacer. ACK propio todavía transmite snapshot; metadatos, orden y revisiones pueden ser completos. El agregado comercial y su lock limitan el crecimiento: no se declara escalabilidad ilimitada ni sincronización garantizada con la app cerrada.

## 5. Seguridad, backend y costo

Backend opcional autorizado: organización **kkshiiit**, proyecto **lttfkynkhveomntejqhc**, Supabase **Free**, siete migraciones. Edge `chema-api` fue probado en v5 y restaurado en **v7 ACTIVE** tras limpieza QA; archivos idénticos verificados, bundlev7 `dae8644a179e947053387766ce33b1800149d487cb1b59b7d6a33b149fd11acf`. No hay tarjeta, upgrade ni complemento pago activado por este trabajo.

El gateway `verify_jwt=false` permite únicamente el aprovisionamiento por invitación privada; las demás acciones validan Auth y membresía, y SQL revalida dentro del commit. RPC privilegiadas sin EXECUTE para PUBLIC/anon/authenticated; tablas de servidor con RLS y acceso directo revocado. No se usa user_metadata para decidir permisos. Cliente contiene URL/clave publicable, nunca service_role. Sesión nativa en SecureStore; copia local separada por espacio/uid. Conocer una revocación bloquea acceso y envíos sin borrar la cola. No se promete borrar instantáneamente datos ya vistos por un teléfono offline.

Avisos de seguridad: nueve INFO `rls_enabled_no_policy` corresponden a tablas de servidor deliberadamente inaccesibles al cliente; no se añaden políticas amplias para silenciarlos. Sigue WARN de protección de contraseñas filtradas desactivada, dependiente del plan. Mitigación: contraseña fuerte, invitación privada de un uso y recuperación administrativa; no se activó Pro ni se confundió email ingresado con titularidad verificada.

`npm audit --omit=dev` devolvió **ocho nodos afectados: cuatro altos y cuatro moderados**, no ocho vulnerabilidades independientes. Tres avisos base: `node-forge`≤1.4.0 (GHSA-86w9-cpqp-85rv), Zod<4.6.6 (GHSA-mrhx-c7xc-m3w5) y uuid<11.1.1 (GHSA-w5hq-g745-h8pq). Los dos primeros alcanzan dependencias de ExpoCLI; el dominio usa Zod4.6.6. El aviso uuid afecta v3/v5/v6 con buffer proporcionado; ExcelJS y xcode inspeccionados usan v4. No se declara ausencia de vulnerabilidades ni explotación demostrada del APK. La actualización segura de herramientas transitivas queda pendiente; no se aplicó el downgrade mayor de Expo54/Excel3.4 propuesto automáticamente por npm ni se forzó Zod4 sobre una CLI que depende de3.

Fuentes oficiales reconsultadas: [egreso](https://supabase.com/docs/guides/storage/serving/bandwidth), [tamañoDB](https://supabase.com/docs/guides/platform/database-size), [backups](https://supabase.com/docs/guides/platform/backups), [contraseñas](https://supabase.com/docs/guides/auth/password-security), [cuotas](https://supabase.com/docs/guides/platform/billing-on-supabase). JPEG autenticado por Edge normalmente consume la parte uncached. Puede haber pausa, restricciones y cambios de condiciones. No se garantiza gratuidad ilimitada, disponibilidad permanente ni backup automático gratuito. El modo individual no requiere servidor y conserva operación si falla el equipo. No se agotó una cuota ni pausó realmente el proyecto para probarlo.

**Copia operativa pendiente:** JSON de equipo protege estado/propuestas e historial **disponible en ese teléfono**, no todo el ledger de servidor. Respaldo administrativo debe incluir SQL/esquema, historial completo, Auth según procedimiento autorizado y objetos privados con manifiesto; un dumpDB no contiene binarios Storage. Antes del piloto comercial se necesita frecuencia, destino y prueba de restauración de esa copia. No se inventaron credenciales ni un responsable comercial.

**Limpieza comprobada:** cuatro cuentas QA `example.invalid`, dos espacios desechables y dos JPEG631 bytes fueron eliminados con guardas. El helper temporal quedó retirado al restaurar los archivos de Edge; no quedó endpoint permanente de limpieza. Scripts/evidencias en `limpieza-qa*`. No reutilizar las credenciales QA ya eliminadas.

1. **Proteger instalación:** exportar copia JSON con fotos fuera de la app; anotar versión/Android/modelo. Instalar encima, nunca desinstalar ni borrar datos. Si no ofrece Actualizar o rechaza firma/código, detenerse y enviar el mensaje exacto.
